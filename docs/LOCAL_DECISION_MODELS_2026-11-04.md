# Local Jev-style decision models — TraceCart benchmark (2026-11-04)

## Scope and decision

This is a **research-only**, read-only comparison of local decision models.
It does **not** replace the existing final-verdict engine, change the user
interface, or visit any retailer. The downloaded checkpoints are installed
in the existing Ollama instance; no server settings were changed.

Currently Qwen 2.5 1.5B is called through a single inference worker with
a 24-second timeout and returns one evidence-classification category.
The purchase summary and honest missing-evidence fallback are already
generated deterministically. Delaying the visible deterministic assessment
until the optional model finishes is unnecessary.

## Environment

- hexagony-01: 62 GiB RAM and GTX 1050 Ti (4 GiB VRAM).
- Ollama 0.40.13 bound to 127.0.0.1:11435 (local).
- Installed: tev1:0.8b, tev1:4b, pre-existing qwen2.5:1.5b-instruct.
- API: POST /v1/systemone (Tev1); POST /api/chat JSON-schema (Qwen).
- Ollama /api/ps reported **0 bytes of VRAM used by either Tev1 model**.
  The measured Tev inference therefore ran on CPU, not on the Nvidia card.

## Data and labels — important limitations

The 11-case suite includes **five saved TraceCart research records**
(Dell, Ryobi, Lenovo, bicycle, detergent) and **six synthetic
counterfactuals** based on them. The saved observations are not live seller
confirmations. Counterfactuals include an exact-model conflict, an index
quote with a corrected magnitude, an omitted coupon, and invented positive
checkout receipts (only in benchmark data).

One source record shows a seller-listed 3499.99 PLN, a conditional
2799.00 PLN coupon (not checkout-verified), and an indexed quote of 139.95 PLN
that must not be treated as a reliable product total.

Reference labels are produced by the deterministic triage policy coded in
the benchmark:

1. SKU/model conflict -> VERIFY_VARIANT.
2. Same-seller indexed quote less than 25% of browser-listed price ->
   RECHECK_INDEX.
3. Conditional coupon without checkout application -> VERIFY_COUPON.
4. Exact-model and delivered checkout receipt both verified ->
   ACCEPT_RECEIPT.
5. Otherwise -> VERIFY_SELLER.

This evaluates **policy reproduction**, NOT real-world retail prediction
accuracy, seller fraud detection, or probability calibration. The 25%
threshold is a benchmark-specific illustration, not an approved production
heuristic. A deterministic classifier scores 100% on labels generated by
its own rules; that does not constitute an independent accuracy result.
No human-labelled purchase-outcome test set exists yet.

Qwen and Tev receive the same classification problem in this evaluation,
but production Qwen's final verdict is a different three-class task:
the times are indicative of local *triage* only.

## Reproducing the experiment

Run on the saved local 8810 research service and local Ollama.
No new merchant fetches, paid requests, browser captures, or cart writes:

    python3 benchmarks/local_decision_models.py \
      --cart-server http://127.0.0.1:8810 \
      --ollama http://127.0.0.1:11435 \
      --output /tmp/tracecart-local-decision-benchmark.json

Only read-only localhost GETs for existing cart status and graph JSON,
and local Ollama POSTs, are made. Inputs are a bounded data projection, not
full HTML, cookies, tokens or customer accounts. Results remain in /tmp.

## Measured results

The existing deterministic final-evidence fallback was also timed using
fully built, saved decision projections and their corresponding graphs
(only CPU function execution; HTTP transfer and graph construction excluded).
Per-case times: 12.19, 8.591, 8.837, 5.580, and 9.618 milliseconds;
**median: 8.837 ms**. This produces an advisory non-LLM summary with
explicitly unverified checkout status; it is not a confirmed best-buy verdict.

Model classification on the **same eleven policy-controls** (all eleven
calls returned valid typed answers; the first call also includes model
loading/warm-up):

| Engine | Policy rules reproduced | Median latency | p95 latency | Explicit unsafe omission |
| --- | ---: | ---: | ---: | --- |
| Deterministic rule oracle | 11/11 (by construction) | near-zero | near-zero | None within the written rules |
| **Qwen 2.5 1.5B** (short JSON prompt) | **8/11 (72.7%)** | **1.696 s** | 7.765 s | Missed the coupon case and two simulated positive receipts |
| Tev1 0.8B | **8/11 (72.7%)** | **4.906 s** | 7.345 s | Missed low-index Dell anomaly, conditional coupon, and misflagged bicycle as variant conflict |
| Tev1 4B | **10/11 (90.9%)** | **30.466 s** | 35.481 s | Missed extremely low same-seller Dell index, prioritizing coupon instead |

All numbers are **measured here** (same localhost service, same policy
examples), not manufacturer benchmarks. Qwen's 1.696 s result is for this
**short, special-purpose** classification prompt; it must not be presented
as measured latency for the existing full production final-verdict pipeline,
which has a longer prompt and can hit the 24-second deadline. This is not
a blinded human-outcome evaluation, and eleven samples cannot validate
probabilities or establish domain-specific superiority.

**Decision:** Neither local Tev model should replace the final-verdict
pipeline on this host. The smaller one is slower than short-prompt Qwen
and fails 3/11 policy controls. The larger one exceeds the 24-second
production deadline on almost every case and still misses the important
misleading index quote example. The existing deterministic fallback is
millisecond-scale and already preserves source provenance / verified-status
boundaries. Displaying this result immediately, then asynchronously doing
additional semantic analysis *only when useful*, is the strongest next
engineering step. Do not promote an LLM's choice to a verified purchase
decision. GPU acceleration is not established here: Ollama reports 0 model
bytes in VRAM for all models tested.

Compact, source-URL-free raw classifications and latencies are preserved in
[LOCAL_DECISION_MODELS_2026-11-04_RESULTS.json](LOCAL_DECISION_MODELS_2026-11-04_RESULTS.json).

## Integration policy

Do **not** use decision-model probabilities as evidence that a seller price,
exact SKU, coupon, checkout total or payment was independently verified.
For real usage, immediate deterministic evidence and source provenance must
win. For ambiguous semantic cases, require human-reviewed labels and an
out-of-sample evaluation before introducing a probabilistic component.
